# Contributing

1. Discuss substantial behavior or protocol changes before implementation.
2. Explain user-visible behavior and link related issues in the pull request.
3. Run `./scripts/check.sh` and add tests proportional to the risk.
4. Keep user content, secrets, queries, paths, and clipboard payloads out of logs and fixtures.
5. Sign commits with a DCO trailer: `Signed-off-by: Name <email>`.

Public domain and extension APIs require documentation. New dependencies require an ADR covering maintenance, license, binary size, network behavior, supply-chain risk, alternatives, and removal cost.
